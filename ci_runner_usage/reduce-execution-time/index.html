Axis 1 · Reduce test execution time

Plan · Nov 3, 2026 · Keep the same tests and coverage, spend less time per run. Removing or demoting tests is axis 2; the two pages share the decisions below.

1. Reduce execution time 2. Test audit 3. Selective filters / labels 4. Compile cache

Why it's slow

  • Every e2e test builds its own engine. No test shares an LLM through a module- or session-scoped fixture, and many build two (TP1 and TP2, fp16 and fp8, APC and plain, transformers and native). Most of the time goes into build and compile, not into the checks.
  • The same model is built over and over. Four test_compile tests and three test_kernel_cache cases each build the same compiled micro-g3.3 config, and the two compiled Ministral-14B tests share one config.
  • Full-size models are used where a small one would do. Most multimodal tests only check text.strip(), yet they load 14–26B of weights.
  • Two legs run one test each and set the wall clock. smoke-0 runs only the gemma-4 image test (41.5 min) and distributed-0 only the TP2 image test (47 min). The other legs take about 28–31 min.

Phase 1 · Consolidate and truncate (no coverage change)

E1 · One Ministral-14B compiled engine for the text-only and image checks

~25 minEffort Stests/e2e/test_multimodal.py

Change: merge test_single_image_prompt_produces_output[compiled] (26.5 min) and test_warmup_covers_text_only_token_embedding_on_multimodal_model (24.9 min), which call _generate with the same config. Let _generate take a list of prompt batches and run them on one LLM, text-only first, then the image prompt.

ProsBoth checks stay, and one full 14B build and compile goes away.
ConsThe compile guard is read once, when the worker starts, so both prompts run at the same guard level. A failure in the first step also hides the result of the second.
Recommended
  • Action: do this first; it's the best saving per hour of work.
  • Mitigation: run the whole test under SPYRE_COMPILE_GUARD=error. The vision tower is already warmed: test_tp2_compiled_image_prompt_matches_tp1 runs the same image prompt under error today. Run the image prompt last and give each check its own assertion message, so a failure names the check that broke. (pytest-subtests isn't a dependency, so don't rely on it.)

E2 · Truncate gemma-4 in the TP2 parity test

27.2 → a few minEffort S/Mtests/e2e/test_distributed_tp2.py

Change: in the gemma-4-26B-A4B-text param of test_tp2_compiled_llm_generate_matches_tp1, pass hf_overrides={**GEMMA4_TEXT_BACKBONE_OVERRIDE, "num_hidden_layers": 6}. The backbone override already makes the text config the model config, so the key goes at the top level, not under text_config.

ProsTP1 vs TP2 still compares like with like: both sides are truncated the same way and use real weights. Every 26B-A4B layer is MoE, so MoE and all-reduce stay covered.
Cons6 layers is the floor: the first five are sliding-window, and the first full-attention layer is index 5. Bugs that appear only at full depth (later layers, long KV) are no longer caught per PR.
Recommended
  • Action: do it, and keep the full-depth param as trunk_only.
  • Mitigation: assert in the test that the truncated layer_types contains both sliding_attention and full_attention, so a checkpoint change can't silently drop one. vLLM already deep-merges hf_overrides, so no helper is needed. Needs HW: show in the PR that the 6-layer model compiles at TP1 and TP2.

E3 · Truncate the remaining gemma-4 compile row

~8–10 minEffort Stests/e2e/test_compile.py

Change: the audit moves gemma-4-31B-text to trunk (C1). Truncate the remaining gemma-4-26B-A4B-text row of test_basic_llm_inference with the same "num_hidden_layers": 6 override as E2, and regenerate its reference in test_compile.py.

Prostorch-spyre PRs keep a gemma-4 MoE compile signal at a fraction of the cost.
ConsA truncated model's exact output is arbitrary text, so the reference string has to be regenerated and can't be checked by eye.
Recommended
  • Action: do it, in the same PR as audit C1, so gemma-4 coverage never drops out of the integration tier.
  • Mitigation: generate the reference once from the truncated model, and record the command next to it the way the existing references are recorded. Compare token IDs rather than strings. The quality gate still checks the full model for correctness.

E4 · Fold the compile-guard test into test_basic_llm_inference

~3 minEffort Stests/e2e/test_compile.py

Change: test_warmup_covers_every_compile_a_request_needs uses the same model and shapes as the [micro-g3.3] row and differs only in the guard. Delete it and set SPYRE_COMPILE_GUARD=error in _assert_compiled_output.

ProsThe warmup guard then covers fp8, gemma-3 and gemma-4 too, so coverage grows.
ConsA gemma row may fail on a real warmup gap and block the PR until that's fixed.
Recommended
  • Action: do it in two steps.
  • Mitigation: first set the guard to error for micro-g3.3 and to warn for the others, logging what fires. Once the warnings are fixed, or tracked as an xfail with an issue link, switch every row to error.

Phase 2 · Smaller models and tighter shapes (measure first)

E5 · gemma-4 vision (compiled): switch to a nano gemma-4

~25–30 of 41.5 minEffort Mtests/e2e/test_multimodal.py

Change: point test_gemma4_single_image_prompt_produces_output[compiled] at joerunde/gemma-4-moe-nano, which has 6 layers, 128 experts, a 2-layer vision tower and real weights, and is already in the local HF cache. Add it to .github/cache_config/hf_models_and_datasets.yaml so CI runners have it. The [eager] twin goes to trunk (audit B).

ProsThe run skips the 26B weight read and has fewer graphs to warm up. The architecture is the same, so the tower, projector, MoE and offset-group pool code paths are unchanged. Real weights keep the output meaningful.
ConsCompile time scales with the number of distinct graphs, not with layer count, so the saving may be smaller than expected. The model also lives in a personal HF namespace.
Recommended
  • Action: do it, and compare warmup variant counts in the PR (the warmup logs list them).
  • Mitigation: with the author's OK, mirror the model into an org namespace before CI depends on it. If that isn't possible, fall back to the 26B model with load_format="dummy" (the padded-MLP loader already accepts dummy weights) and SamplingParams(ignore_eos=True). The full 26B stays covered by the quality gate.

E6 · Truncate the TP2 image parity test

~35–40 of 47 min (longest leg)Effort Mtests/e2e/test_distributed_tp2.py

Change: test_tp2_compiled_image_prompt_matches_tp1 builds the 14B twice. Cut the decoder and vision layers with hf_overrides. The test uses config_format="mistral". vLLM applies hf_overrides after it converts params.json, so the overrides do take effect on that path.

ProsRemoves the longest leg in the tier, and the distributed pool frees up first.
ConsThe layer-count key names after the mistral conversion aren't verified until a hardware run. Bugs that show up only at full depth move to trunk.
Recommended
  • Action: start with a half-day spike on hardware that checks the layer counts in the built engine config, and keep the full-depth run as trunk_only.
  • Mitigation: if the mistral key names don't match, use the HF-format config.json the same repo ships (Mistral3ForConditionalGeneration, 40 text and 24 vision layers), where the keys are standard. Only if that also fails, fall back to audit E3 (trunk-only), and keep the micro-g3.3 TP2 parity case as the per-PR TP signal.

E7 · Tighten warmup sizes to what each test's prompts need

~2–5 min per testEffort S each
  • test_multimodal.py: lower MAX_MODEL_LEN from 512 to 256 for the Pixtral rows. test_distributed_tp2.py already serves the same 176×176 image at 256.
  • test_granite_vision.py: sets max_model_len=4096 with no compile_sizes, so warmup covers every bucket up to 4096. Size each test to its own prompt. The multi-tile test goes to trunk (audit C3), so the per-PR single-image test can be much smaller.
  • test_prefix_caching.py[compiled]: max_model_len=512 with four engines. The shared prefix is at least 256 tokens (the test measures it with the tokenizer), so about 320 is the floor.
ProsWarmup records fewer KV × query buckets. Each change is one line.
ConsThe tests stop covering the larger buckets that production serves. A size that's too tight fails noisily.
Recommended
  • Action: do it, one file per PR, with before/after warmup variant counts in the PR description.
  • Mitigation: derive each size from the prompt's token count (tokenize in the test, add a margin) rather than hard-coding it, so a prompt change can't break it. Large-bucket coverage stays in the attention tier and the quality gate, which run at serving lengths.

E8 · Merge the two same-shape KV-determinism tests onto one engine

~4 minEffort Stests/e2e/test_kv_cache_determinism.py

Change: test_logprobs_do_not_depend_on_earlier_requests and ..._in_a_batch both use max_model_len=256 and a 128-token prefill. Merge them into one test function that builds a single engine with compile_sizes=[128, _BATCH_NUM_SEQS, 1] and runs the "earlier requests" check first, then the batch check. A module-scoped fixture won't work: the file is marked uses_subprocess, and the test plugin kills whatever holds the card after every such test.

ProsSaves one engine build, with no change to the test plugin.
ConsThe second check runs on an engine the first has already used, which is exactly the kind of state a determinism test cares about. One failure also hides the other.
Recommended
  • Action: do it as one test, not as a shared fixture.
  • Mitigation: run the "earlier requests" check first, on the fresh engine, call llm.reset_prefix_cache() before the batch check, and give each check its own assertion message. Sharing engines across tests or files would need an opt-out from the plugin's per-test cleanup, which is a bigger change and is left out of this plan.

Phase 3 · CI plumbing

E9 · Fast-fail first stage (R6)

Saves most of a broken runEffort S/M.github/workflows/_test_matrix.yaml

Change: run a first-stage shard, and make the e2e shards depend on it with needs:.

ProsWhen a torch-spyre PR breaks things, every shard fails together. With this stage it costs about 1 runner-hour instead of about 8.7.
ConsA passing run takes longer by the length of the first stage, about 57 min if it runs every non-e2e test.
Recommended
  • Action: do it, but with a slim first stage rather than all non-e2e tests.
  • Mitigation: make the first stage the custom-op tests plus compiled micro-g3.3 test_basic_llm_inference: about 15 min, since the custom-op tests alone take about 12.5. That's enough to catch a global break. Gate it on test_type == 'integration', which is what dispatched torch-spyre runs send, and leave our own PRs (regression or trunk) fully parallel.

E10 · Rebalance shards once E1–E6 land

Wall clock and cards heldEffort SMakefile, _test_matrix.yaml

Change: run the rebalance-test-shards skill. Once the two single-test legs are gone, SMOKE_SHARDS=11 and DIST_SHARDS=3 can shrink.

ProsFewer Spyre cards allocated per run, and a shorter tail.
Constests/test_sharding.py has to stay in lockstep with the matrix. Rebalancing too early locks in stale durations.
Recommended
  • Action: do it last, once, from the durations of 3–4 runs after Phase 2 lands.
  • Mitigation: the skill already keeps the Makefile, the matrix and test_sharding.py in lockstep. Re-run it whenever a leg drifts more than about 20% from the median.
