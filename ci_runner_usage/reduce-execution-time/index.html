Scope

How to make each CI run itself faster, as opposed to running fewer tests (that's axis 2) or running them less often (axis 3).

  • Shard/test consolidation: tests that build the same model or engine more than once within a run (see R3's "build each compiled model once").
  • Cheaper models for output-only checks: layer-truncated configs, load_format="dummy".
  • Tighter warmup buckets so a test only compiles the shapes its prompts actually hit.
  • Fast-fail staging so a globally-broken run doesn't pay for every shard (R6).

Relevant existing findings

From the main report: multimodal/vision tests are ~45% of the integration tier's pytest time and are almost all "produces output" checks on a handful of models (§7 R3). The per-file and per-case breakdowns are in §5 and the raw data in data/integration-tier-tests.json.
