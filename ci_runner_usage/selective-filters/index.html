This page is a placeholder. Related mechanism is proposed in the main report — see R1 and R2 below. This page will hold the labeling scheme and opt-in UX once it's designed.

Scope

Giving tests organizing labels (e.g. integration, integration_heavy, distributed) so a run — whether a PR push, a dispatched torch-spyre check, or a manual invocation — can opt in to only the tiers it needs, rather than running everything in _test_matrix.yaml's current fixed tiers.

  • A marker-based tagging scheme in pyproject.toml / the Makefile, consistent with the existing distributed, upstream, attention_smoke, model_quality markers.
  • A way to select tiers via workflow_dispatch inputs or PR labels, so e.g. a torch-spyre dispatch can request the cheap core only.
  • Making sure matrix entries outside the requested tier never allocate a Spyre runner at all (see R2), not just skip their test step.

Relevant existing findings

The main report proposes a new integration_heavy marker to split the cheap core from the expensive e2e cases (§7 R1), and a planning job that filters the matrix by inputs.test_type before any runner is requested (§7 R2).

Open questions
