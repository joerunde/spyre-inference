Axis 2 · Audit for unnecessary or unrealistic tests

Plan · Nov 3, 2026 · What should exist at all, and in what form. Which tier each test runs in is decided by axis 3; making the remaining tests faster is axis 1. Every item was checked against main, CI data and, where it mattered, Spyre hardware.

1. Reduce execution time 2. Test audit 3. Selective filters / labels 4. Compile cache

Summary

The audit covers all of tests/, measured against one cold integration run: 2,563 cases, 448 pytest-min. The ~2,100 cases under a second add up to about a minute, so it concentrates on the slow ones. This page keeps only what tiering can't do: deleting a test, shrinking it, re-linking it, or adding a cheap replacement.

Eager tests with a compiled twin

Every test that runs on the card in eager mode, matched against the compiled test that covers the same code path with an assertion at least as strong. Checked against main 8144e163. Minutes are cold / warm.

What "eager" actually covers: the default KV layout is head-major, and head-major attention always compiles, even under --enforce-eager (spyre_attn.py). So in a decoder, eager mode only means the transformer blocks run uncompiled and maybe_compile kernels fall through to eager (lazy_compile.py). Decoder attention is the same compiled kernel either way. Code that only eager mode reaches:

  • the vision tower's encoder_eager_forward / embed_multimodal (_vision_encoder.py)
  • encoder attention behind the opaque op (install_encoder refuses eager, spyre_encoder_attn.py)
  • the uncompiled block path that every --enforce-eager user hits

Op-level eager tests are a separate question: they check the eager kernel against a reference, not a serving path. The token-major eager cases in test_spyre_attn (83 cases, 6.2 min warm) are the only coverage of eager token-major attention, and the 60 eager cases in test_spyre_encoder_attn (3.9 min) are the only coverage of the opaque encoder path, so both stay. The padded SDPA, linear and probe eager cases add up to under a minute.

ProsFive eager tests deleted outright. The encoder flip puts the default compiled encoder path into per-PR runs for the first time, apart from one bucketing test.
ConsFlipping the encoder tiers moves the eager opaque-attention path out of per-PR runs. Demoting the eager TP2 test does the same for the eager collective.
Recommended
  • Action: delete the five duplicates (already in Delete). Flip the encoder tests: compiled test_encoder_embed_models_compiled and …rerank…_compiled into smoke and e2e_smoke, eager into regression_extra. Demote test_prefix_caching[eager] and the eager TP2 test. Keep every eager-unique and no-twin test running somewhere.
  • Overcoming the cons:
    • Eager encoder attention: the 60 op-level eager cases in test_spyre_encoder_attn keep checking the opaque path per PR, and the eager-only …mean_multi_seq, …last_pooling and …token_classify tests still run it end to end.
    • Eager collective: serving uses the lowered collective, which the compiled TP2 twin covers per PR. The eager SpyreCCLBackend path is also used by all_gather's list form, so keep the eager TP2 test in regression_extra, not trunk only.
    • Cost of the flip: pick one embed and one rerank model for the compiled set, matching what axis 3 already picks ([30m] and [v2-m3]), so the flip costs about the same as today.

A · Expected failures and stale markers

A1 · e2e/test_kernel_cache.py::test_kernel_cache[tp1-fresh]

Nightly6.9 min cold · 7.5 min warm (costliest case in a PR run)

Evidence: this is a strict xfail(raises=CacheGrewError) for a known cross-process cache-key bug: the fused RMSNorm+mm and attention keys differ between processes. No issue is linked. It still builds a cold and a warm engine on every run, and it's the single most expensive case in a warm PR run.

Change: add pytest.mark.nightly to the param, and link a new issue in the xfail reason.

ProsAbout 7 min off every tier, warm or cold.
ConsA fix is noticed only if somebody watches nightly. It's also the test that the compile-cache axis depends on.
Recommended
  • Action: move it to nightly and file the issue now.
  • Overcoming the cons: keep strict=True. Once the bug is fixed, nightly fails with XPASS, which forces the marker off. Assign the issue to the compile-cache owner, since fixing it unblocks cross-run cache hits.

A2 · Probes whose linked issue has closed

Validated on hardwareRe-link, don't deleteprobe tier

Evidence: in tests/probes/test_spyre_fallback_probes.py, the xfail on test_spyre_lm_head_unpadded_matmul_and_slice tracks #1918, which is closed. The probe tracking the open #3499 also cites #3502 and #3503, both closed. On hardware, both still fail (XFAIL). The bugs are real; only the issue links are stale.

Change: point each reason at a new open torch-spyre issue that describes the current failure.

ProsThe probe tier tracks live issues again, and each probe flags its fix with an XPASS.
ConsAs more issues close, links will go stale again.
Recommended
  • Action: re-link both, and keep the probes.
  • Overcoming the cons: add a small CPU-only check on ubuntu-latest. It reads issue numbers from xfail(reason=…) only, not from comments, treats a bare #N as torch-spyre, and flags any that are closed.

Rollout

  1. Delete PR: the five tests in Delete, with the capability tag moved first. About 14 cold min off every tier.
  2. Encoder flip and eager demotions: in axis 3's marker PR, compiled encoder embed and rerank go into e2e_smoke, eager into regression_extra, and the eager TP2 and prefix-caching tests are demoted (eager vs compiled).
  3. No-loss PR: F1 (shrink), the C2 and E1 CPU tests, and pruning the 40 always-skipped attention cases.
  4. With axis 3's marker PR: the items in Handled by axis 3 move tiers there; C1 and E3 land together with axis 1 E3 (nano gemma-4), so each demotion comes with its per-PR replacement.
  5. Infrastructure: a nightly marker with its cron workflow, and the Slack trunk-failure alert; then A1.
  6. Probe hygiene: A2 re-links, the int32 xfail's issue link, and the closed-issue checker.
  7. Owner call: re-enable or delete the batched-decode cases.
  8. Ongoing: review with axis 3 quarterly; query ClickHouse for slow tests that haven't failed in 30+ days.

How this was validated
  • Code: every item was checked against main 593b5709, and the deletion list again against b1d80f8e. Every linked issue's state was checked against GitHub. A deletion needs evidence that another running test holds the coverage. No tests of removed code, dead env flags or superseded tests were found.
  • CI data: JUnit timings from regression run 41691109984, integration run 41512695264 and the original dataset run 41363344874.
  • Hardware: the probes (A2), the nano replacement for C1 and E3, and the truncation attempts all ran on the team's 4-card Spyre host. Its torch-spyre is older than main's pin (64870622 vs f8a09bb).
