Status: stub — not yet written up. Part of the CI runner usage effort.

This page is a placeholder. The main CI runner usage report already starts this audit — see R4 below. This page will hold the full case-by-case audit once it's done.

Scope

Finding tests that cost runner time without buying signal: expected failures, duplicates, output-only checks on models the quality gate already covers, and cases that haven't failed in a long time.

  • Known xfails that never turn green (e.g. test_kernel_cache[tp1-fresh], see R4).
  • Eager/compiled duplicate pairs where only one adds coverage.
  • Tests that only assert non-empty generation on a model the model-quality / GSM8K gate already checks for correctness.
  • Cases with no failure in ClickHouse history over a long window — candidates for demotion to trunk or manual.

Relevant existing findings

From the main report: of ~2,560 integration-tier cases, ~450 take more than a second and are worth auditing; the rest total about a minute combined (§7 R4). Per-test history is queryable from the JUnit data push-to-clickhouse.yaml already ingests. Full per-case data: data/integration-tier-tests.json.
