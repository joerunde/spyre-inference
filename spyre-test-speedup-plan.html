A small same-architecture model for every family

Spyre correctness is validated per model architecture, so the lever is not one micro model for everything — it is a real, scaled-down checkpoint of each full model's own architecture, found on HuggingFace and verified by config. The default suite keeps per-architecture coverage cheaply; the full product models move to an opt-in suite.

The idea, corrected

We can't cleanly separate "is the Spyre code correct" from "does this model run" — correctness is tested per architecture, because each family (gemma-4's dual head-dim + MoE FFN, Pixtral's conv-patch vision, the XLM-RoBERTa classifier head) exercises a different Spyre lowering. So the substitute for a 31B model is not micro-g3.3; it is a genuinely smaller checkpoint of that same architecture.

Those exist on HuggingFace for almost every family. The plan: the default suite runs a small same-architecture probe per family (full numerical check against a cached reference, cheap), and the opt-in full_model suite runs the actual product models for the load-and-run proof we have no external eval for. Per-architecture coverage stays on every PR; only the full weights leave the critical path.

One architecture has no small checkpoint on HF: gemma-4 MoE (gemma-4-26B-A4B and its -it vision sibling) — and it is the biggest single cost (TP2 + vision + compile ≈ 72 integration card-min). Every public small MoE-gemma-4 is a tiny-random stub with head_dim 16/32, which violates Spyre's head-size rule. So we generate our own: the real config shrunk only in size, with controlled init — see §02. That turns the one unavoidable family into a substitutable one, pending a one-time on-hardware validation.

02 Generating the gemma-4 MoE micro model

No public small MoE-gemma-4 has a Spyre-valid head size, so we build one. Its tests check Spyre-vs-CPU numerical agreement, TP1-vs-TP2 consistency, and "produces output" — never output quality — so the weights need only be numerically well-behaved, not good. This is a conditioning pass, not distillation (no teacher, no 26B download).

Config: inherit, then shrink only size

Derive the config by loading google/gemma-4-26B-A4B-it and overriding only the size fields, so every architecture flag is inherited verbatim rather than hand-typed.

Keep verbatim — defines the Spyre pathShrink — defines the size
head_dim 256, global_head_dim 512, num_global_kv_heads 2, vision head_dim 72text layers 30 → ~6 (keep ≥1 full + sliding)
enable_moe_block, num_experts 128, top_k_experts 8hidden_size 2816 → ~256
layer_types (full every 6th) + dual rope (proportional / default)moe_intermediate 704 → ~64, intermediate 2112 → ~128
GQA 16/8 heads, sliding_window 1024, full vocab 262144 + real tokenizervision layers 27 → ~2

Keeping the full 262144 vocab and the real tokenizer makes the checkpoint embedding-dominated (a few hundred MB, not a few MB) — still trivially fast against 26B, it exercises the real vocab-parallel LM-head/embedding path, and it lets training use any text with no custom tokenizer. head_dim 256 is already a multiple of 64; vision 72 matches the real model, so both take the real Spyre paths.

Weights: controlled init, optional light pass

  • Controlled init first (free). transformers' default init with a small std; verify the forward pass is finite and the logit distribution isn't flat. Often enough on its own.
  • Light LM pass only if needed. A few hundred next-token steps on a small generic corpus (wikitext-2 / C4 slice), bf16 then cast — minutes of compute — to peak up the distribution and avoid fp16 softmax overflow. Stop when logits are stable, not at a loss target.

Deliverable & gate

  • tests/data/generate_micro_gemma4_moe.py — reproducible (seeded, pinned corpus + transformers version); emits the checkpoint and regenerates its decoder reference.
  • Host as ibm-ai-platform/micro-gemma-4-moe, mirroring how micro-g3.3 is hosted; the script stays in-repo for audit and regeneration.
  • Gate: one on-hardware run confirming the shrunk config lowers on Spyre identically to the full model (new, complex architecture — the real unknown). If it doesn't, gemma-4 MoE falls back to full-size opt-in.

03 What else this costs to build

Substituting a model isn't free plumbing — the correctness tests compare Spyre output against a cached CPU reference keyed by model id, so each new small model needs its reference generated once.

  • Decoder quality — regenerate tests/data/decoder_output_refs.json for the small models via generate_decoder_output_refs.py (CPU run, one-time). Then the default list is the small models; the full list is marked full_model.
  • Encoders — add reference entries in encoder_embed_refs.json / rerank_score_refs.json for the -base models (the test skips a model with no ref, so this is required).
  • Compile / TP2 / multimodal — these assert output shape or an exact decoded string, not a cached tensor, so swapping the model id is enough; no reference regen.
  • Marker wiring — declare full_model in pyproject.toml; mark the full-size rows with pytest.param(…, marks=pytest.mark.full_model) (compile, TP2, encoder lists) or @pytest.mark.full_model (quality decoder/fp8, VLM tests); add and not full_model to the smoke / distributed / quality MARK_OVERRIDE in the Makefile; add a test-full-model-shard target + FULL_MODEL_SHARDS and matrix legs tagged regression trunk (not integration, not unit) so the opt-in suite never runs on torch-spyre's PRs or the default per-PR gate. Needs a 1-card and a 2-card leg (the TP2 case).
  • Coverage — the opt-in suite runs nightly + on workflow_dispatch + an opt-in label; tests/test_sharding.py keeps Makefile and matrix shard counts in lockstep.

05 Suggested rollout

  1. Gate gemma-4 MoE to opt-in immediately
    Mark TP2 (33.8 card-min, 2 cards), the gemma-4-26B-A4B compile row, and the gemma-4 vision tests full_model. Biggest integration-tier win, zero build work, ends the ~30-min smoke shards — default loses gemma-4 MoE coverage only until the next step lands.
  2. Generate + validate the gemma-4 MoE micro
    Build micro-gemma-4-moe (§02), validate once on a card, host it, then add it as the default probe to restore per-architecture coverage on every PR.
  3. Substitute the decoder quality + fp8 families
    Add small-model references (granite-3.3-2b, granite-4.1-3b, gemma-4-E2B, granite-4.2-3b-fp8), mark the 8B/31B rows full_model, drop the Llama-3.1-8B row (already covered by Llama-3.2-1B). Recovers the 20-min quality shards.
  4. Substitute the Pixtral + encoder families
    Ministral-3-14B→3B, bge-reranker/e5/roberta → -base. Keep one cheap VLM (granite-vision tiny or 2–3B) in default so the multimodal path still runs per-PR.
  5. gsm8k
    Substitute mistral-7b→tiny-mistral for the arch probe; keep the real models in the opt-in eval, and separately evaluate num_questions 64→32 with an accuracy-vs-noise check.
  6. Measure, then re-shard
    Time the chosen substitutes once to confirm the add-back, then re-run rebalance-test-shards — smoke and quality shard counts should fall, reclaiming the earlier 8→10 smoke bump.

Method & caveats

  • Substitute architectures were verified by reading each candidate's live HuggingFace config.json on 2026-10-08: matching architectures + model_type, matching MoE-ness / vision-tower family / fp8 quantization, and head_dim a multiple of 64 (Spyre's head-size rule). Tiny-random stubs were rejected on head_dim even when the architecture matched.
  • Durations are from one full trunk run (37519695361); exact seconds carry run-to-run variance. Small-model runtimes are not yet measured — the add-back range is an estimate from already-measured 1–3B models.
  • Card-minutes weight distributed/TP2 legs at 2 cards, everything else at 1. The integration tier is exactly smoke + distributed.
  • gemma-4-E2B and the Llama checkpoints are license-gated; CI already authenticates to pull today's gemma-4/Llama, so this adds no new blocker. The granite-vision 0.2B tiny is a community repo — a maintainer call vs. an official 2–3B floor.
  • Substituting a decoder/encoder model requires regenerating its cached reference; that reference is itself a CPU-side correctness anchor, so coverage of the small architecture is genuine, not shape-only.
  • The gemma-4 MoE micro is generated by us (no public small checkpoint has a Spyre-valid head size). Weights are controlled-init, optionally a short LM conditioning pass — the tests check Spyre-vs-CPU agreement, TP1-vs-TP2, and "produces output," none of which need a quality model. It is gated behind a one-time check that the shrunk config lowers on Spyre identically to the full model.
