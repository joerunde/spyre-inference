Why gemma-4's prefill kernel recompiles

Found while triaging #1547 (torch 2.14.1 + torch-spyre fa54674e). The same failure shows in main's integration runs, which build torch-spyre main.

In one breath
  1. torch-spyre#5976 makes model.to("spyre") keep each weight's Python object. vLLM's ModelWeightParameter subclass now survives the move.
  2. Gemma-4's MoE router (GateLinear) isn't one of our OOT linears, so it calls F.linear on that subclass and Dynamo inlines its __torch_function__.
  3. Dynamo then wraps the whole compiled decoder-layer graph in DisableTorchFunctionSubclass(). Attention runs inside that graph, so at serving time our prefill kernel is called with __torch_function__ off, while warmup traced it with it on.
  4. The kernel's guard sees GLOBAL_STATE changed: torch_function and recompiles. SPYRE_COMPILE_GUARD=error turns that into the test failure.
1 · The trigger

torch-spyre#5976 keeps the weight's class

Before the change, load_model_to_spyre replaced every parameter with a fresh nn.Parameter. The subclass, and its __torch_function__, were dropped on the way to the device. Now the device tensor is swapped into the original object.

2 · Who touches the subclass

Only the router goes through vLLM's F.linear

Every ColumnParallel/RowParallel/QKV/Replicated linear is replaced by our OOT class. After loading, it stores Wᵀ in a fresh plain Parameter and matmuls that. GateLinear subclasses ReplicatedLinear but isn't registered as OOT, so it keeps vLLM's UnquantizedLinearMethod and the original ModelWeightParameter.

3 · What Dynamo does with it

The whole block graph runs with __torch_function__ off

When Dynamo inlines a subclass's __torch_function__ while tracing, it sets torch_function_subclass_inlined and wraps the compiled graph in DisableTorchFunctionSubclass() to avoid dispatching twice (torch/_dynamo/output_graph.py, _tf_disabled_wrapper). torch 2.13 does the same; this part isn't new.

4 · Why it recompiles

Warmup and serving see different global state

Warmup records every attention variant by calling the kernels directly, outside any block graph, with __torch_function__ on. Dynamo's GlobalStateGuard captures that. The first real prefill arrives through the wrapped block with it off, so the guard misses.
