Speculative decoding (DFlash/XPress) on the V2 runner

Plan for #1575 (part of #906). vLLM v0.33.0, spyre-inference main at 4178907. Written before implementation, then self-reviewed (section 6). Implemented on mrv2-spec-decode-1575: on Spyre with the locked RPMs, XPress on V2 is token-exact against the target alone for Qwen3-8B (one request and a batch of four) and Gemma 4 26B A4B (#1521's prompts, one past the draft's 2048-token window), with SPYRE_COMPILE_GUARD=error and FallbackWarning as an error. Gemma 4 acceptance matches V1's on the same prompts.

In one paragraph. Upstream's MRV2 runner already drives a speculator through one seam. It builds self.speculator, loads it inside load_model, gives it attention groups in initialize_kv_cache, and calls propose(...) after every sampled step, then reads the result from req_states.draft_tokens. We keep all of that and replace only the speculator: one class, SpyreDFlashSpeculator(DFlashSpeculator). Upstream's propose, with its Triton input-prep kernel, runs as-is on x86; the speculator overrides the hooks where the draft crosses onto Spyre, and its loader moves the draft there. The rest is removing five refusals and fixing three things they were hiding: aux-hidden-state wiring, lm_head row buckets and draft attention recording.

Scope: x86 only, on as many of upstream's Triton kernels as possible. Host replacements for Power and Z follow with the rest of MRV2's kernels (#1238).

2. The speculator

New module spyre_inference/v1/worker/spyre/spec_decode.py, about 130 lines. It subclasses DFlashSpeculator for both draft architectures and keeps upstream's propose, so the bookkeeping, the Triton input-prep kernel and the context-limit and prefill handling are all upstream's. Our draft model already handles both architectures through propose_block (XPress refines when it has a head), so nothing in XPressSpeculator applies: its body is the Triton Jacobi refinement and the DSpark loader.

MethodWhy it differs from upstream
load_draft_modelsuper(), then move_model_to_spyre and prepare_for_spyre()
set_attnsuper(), then the target's sliding-window split, then each draft attention group's causality pinned on its builder: Spyre's single KV group can hold both causal and non-causal draft layers (Gemma 4)
init_cudagraph_manager, captureA manager whose dispatch pads the draft step to 1, 2 or 4 requests and reports CUDAGraphMode.NONE, so the draft runs on shapes warmup compiled; nothing to capture

_generate_draftpropose_block → draft_tokens. On a padded step, first republishes the draft builders' slot mapping at the padded width: upstream's eager metadata covers only the real rows, but the traced KV write needs one slot per row

4. Tests

  • tests/mrv2/spec_decode/test_speculator.py (CPU), against a recording draft model: the draft step pads to a power of two; context stays at the target's padded width with padding on the null page; a padded draft step publishes null slots for its padded rows and an unpadded one leaves upstream's; a warmup dummy stores context without running upstream's branch, and a real step does run upstream's propose; warmup drafts every padded batch once; the set_attn override splits after upstream; the runner replaces upstream's speculator. Upstream's bookkeeping is not re-tested here. Also: upstream's aux-layer setup accepting an EAGLE-3 target's wrapper (and refusing a plain one), and draft causality in attention recording.
  • Updated, for refusals that are gone: test_switch.py, test_kv_cache.py, test_load.py, tests/spec_decode/test_dflash_config.py.
  • tests/e2e/test_xpress_v2.py (Spyre, model_quality, not in the integration tier), with SPYRE_COMPILE_GUARD=error and FallbackWarning as an error. One fresh interpreter per model runs a target-only engine and then the speculative one; greedy output must be token-exact between them, with nonzero acceptance. Qwen3-8B + XPress-b16 runs a batch of four of different lengths, which reaches draft batches 4, 2 and 1 as requests finish. Gemma 4 26B A4B + XPress-b16 runs #1521's short prompt and its prompt past the draft's 2048-token window, and must accept at least half its drafts. Throughput and ITL against V1 are on the PR, relative only.
  • Deleted: V1's XPress e2e tests (test_speculative_decoding.py, test_xpress_batch.py, test_gemma4_xpress.py) and their validation workers. V1 is removed next, and the V2 test costs less CI time than they did. test_xpress_feedback.py (the XPress head on device) and the tests/spec_decode unit tests keep the shared core covered.

5. Out of scope / follow-ups

6. Self-review

What I found re-reading the first draft against the code, and what changed.

FindingResolution
bugThe issue suggests putting keep_aux_hidden_states_on_device in the wrapper, but the real blocker comes earlier. Upstream's set_eagle3_aux_hidden_state_layers receives the wrapper, which fails isinstance(_, SupportsEagle3): a runtime-checkable Protocol doesn't see __getattr__ forwarding (checked). Load would raise.A wrapper subclass, _SpyreEagle3ModelWrapper, declares the protocol's five members by forwarding them, and the loader uses it only when the bare model passes supports_eagle3. (A first version swapped the upstream function for one call; review asked for no new global patches.)
bugV2's load.py builds the lm_head row buckets without the speculative tokens (V1 passes them). Verify steps project num_reqs × 16 rows, which pad to no bucket and compile on first use: a compile-guard error.Pass runner.num_speculative_steps. The compute_logits branch in warmup already warms widths beyond the sampled batch.
riskDraft layers share the target's KV group and head count, so the target's attention group also lists them, and its builder installs a slot holder on them. The draft's builder installs its own afterwards and wins.Correct, because set_attn runs after the target's init_attn_backend (both are in initialize_kv_cache), and recording uses the draft builder for draft layers. The e2e covers it: a wrong holder writes draft KV at target slots and breaks token-exactness.
designThe first version replaced upstream's whole propose with a port of V1's propose_spyre, all on the host and Triton-free.Review set the scope to x86 on as many of upstream's Triton kernels as possible, so upstream's propose now runs as-is and only the Spyre hooks change. Bookkeeping fixes upstream reach us without a port. Behaviour now follows upstream: a block near the context limit is clamped rather than skipped, and prefill chunks draft too; rejection keeps the output exact either way.
bugGemma 4's draft (#1521) has causal sliding-window layers and a non-causal full layer. Spyre disables the hybrid KV cache manager, so all draft layers share one KV group, and upstream's per-KV-group causality gave all five the full layer's value. Token-exactness hid it; acceptance was lower than V1's.The set_attn override pins each draft attention group's causality on its builder (causal_override), and refuses a group whose layers differ. Gemma 4 acceptance on #1521's prompts went from 104/120 to 107/120, V1's figure.
riskTwo hooks cover what Spyre's fixed shapes need that upstream's eager path doesn't: the warmup dummy branch in propose, and republishing padded slots in _generate_draft.Both found on hardware, not by reading, and covered by unit tests. They are the parts most likely to need attention on a vLLM bump.
simplifyThe first draft swapped init_speculator as a module global, like the swaps in load.py.Replace self.speculator after super().__init__ instead. Upstream only stores it there, so there's no patch that can silently no-op. The cost is one throwaway upstream construction (small host buffers).
scopeThe draft's window split is dead code today: validation requires full attention in every draft layer.Kept, as a set_attn override on the speculator (a first version swapped the speculator module's init_attn_backend import). It's a few lines, and it's the piece #1521 needs. The split stays inside each KV cache group, so the group ids and causality upstream's set_attn derives still hold.
checkedV1's builder-ordering fix (initialize_attn_backend re-creating builders).Not needed: MRV2's init_attn_backend groups every layer before it creates any builder.
checkedDraft pages: num_lookahead_tokens = K+1 for DFlash makes the scheduler allocate the draft block's pages, and the context-limit rule keeps its positions below max_model_len.The same invariant V1 relies on.
