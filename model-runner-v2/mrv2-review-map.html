The V2 runner is built beside the V1 runner, and both call the same shared modules for everything Spyre-specific. The diagram shows which pieces each PR in the stack touches.

Why the shared modules matter. Before any V2 code was written, five extract-only PRs (#1275, #1317, #1319, #1320, #1395) moved about 710 lines out of the V1 runner into the modules in the middle column. V1 kept passing its tests on the shared code, so V2 starts from code that is already proven rather than a rewrite.

  • This stack keeps to that rule. Where V2 needed something V1 already had, it moved the V1 code into a shared place instead of copying it: model_dtype and unwrap_model (#1441), rewarm_after_reload (#1441) and the wrapper's outputs_on_host (#1449).
  • So the V2 column is thin: it adapts vLLM's MRV2 runner to Spyre, and the Spyre behavior itself lives in one copy.

#1441

Load and compile

ready for review · on main

Issue #1242, startup

  • V2 loads a model by running vLLM's own load_model with a Spyre loader swapped in. The loader runs the same shared steps V1 does: padding, KV scales, the move to Spyre and per-block compile.
  • All four swapped upstream names live in one place, and loading fails loudly if a vLLM upgrade ever bypasses one.
  • Refuses what V2 can't do yet: LoRA, speculative decoding, batch-sharded sampling.
  • Moves unwrap_model, model_dtype and rewarm_after_reload into shared code that V1 now uses too.
