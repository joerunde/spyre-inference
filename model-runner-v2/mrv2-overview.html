Moving Spyre onto vLLM's Model Runner V2

vLLM is replacing its model runner. Ours inherits from the old one, so it has to move before that one is deleted. This deck covers what changes upstream, how we split our runner to make the move safe, what the V2 runner looks like now, and the order we finish in.

Upstream, vLLM v0.33.0

Two model runners, one going away

V1 is one large class that does input prep, sampling and spec decode itself. V2 splits those jobs into components the runner calls, and writes the per-step host work as Triton kernels. Spyre's hosts have no GPU, so every Triton box on the right needs a host replacement. Click any box to open its source at v0.33.0.

  • vLLM component
  • C++ / CUDA kernel
  • Triton kernel
  • badge = kernel count in that file
  • The deadline is upstream'sOur runner subclasses V1's GPUModelRunner. vLLM 0.34 is expected to delete it.
  • V2's seams suit us betterWe swap a component instead of overriding 37 methods of one class.
  • Triton is the real costEvery Triton box needs a host version for Power and Z. x86 runs them through triton-cpu.

Two runners, one shared core

Before writing any V2 code, five extract-only PRs moved the Spyre logic out of our V1 runner into shared modules. V1 kept passing its tests on them, so V2 starts from code that already works on hardware. Pick a stage to see which modules each runner uses for it, and narrow it to one model kind.

04
Plan

From opt-in to the only runner

Five stages, each gated on the one before it. The hard date is upstream's: V1 has to be gone before we take the vLLM release that deletes it.

now · vLLM 0.33

V2 runs as an opt-in

in progressvLLM 0.33
  • Load, compile, warmup and multimodal are on main (#1441, #1449); #1451 and #1452 are in review.
  • Decoder, pooling and multimodal match V1 on hardware: token-exact, or cosine 1.0.
  • Turned on with SPYRE_MODEL_RUNNER=v2; V1 stays the default.

Done when the bring-up stack (#1243) is merged and CI runs a V2 job.

next

Benchmark and quality on Power and Z

next
  • Bind host kernels for the Triton default path (#1238), then run V2 there for the first time.
  • Compare host time per step and output quality with V1 on all three architectures; fix what regresses.
  • Bring speculative decoding (DFlash, XPress) up on V2.

Done when V2 matches V1 on quality and performance on x86, Power and Z.

then

Make V2 the default

planned · #1244
  • Flip SPYRE_MODEL_RUNNER to v2; v1 stays as a fallback.
  • The full CI suite runs on V2, plus one V1 smoke test.

Done when a release has shipped with V2 as the default and no fallback reports.

vLLM 0.34?

Remove the V1 runner

planned · #1245vLLM 0.34?
  • Delete the V1 runner, its sampler, csrc/ sampling kernels and the fallback flag.
  • Lands with, or before, the vLLM bump that deletes V1; if that bump comes first, hold the pin.
  • From 0.34, revisit vLLM's own CPU runner (vllm#61995) as the base instead of the GPU one.

Done when nothing in spyre_inference/ imports vLLM's V1 runner.

after

Fold the shared modules back in

planned
  • With one runner left, move shared code that only V2 calls next to its caller.
  • Keep a module shared only where more than one V2 component uses it.
  • Drop the workarounds tracked in #1246 as their upstream fixes reach our pin.

Done when the V2 package and the remaining shared modules have one owner each.
