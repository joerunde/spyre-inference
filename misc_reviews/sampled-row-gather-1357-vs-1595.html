Sampled-row gather: #1357 vs #1595

Both PRs keep the decoder's hidden states on Spyre so only the logits cross back to the host. The author reports identical tokens and logprobs for the two. They differ in where they hook into upstream vLLM to get a padded, warmed row count to the lm_head. That choice decides how each one breaks when vLLM changes.

#1357 tensor subclass · runner +115/−27 · tests 229 lines #1595 native index + padded logits_indices · runner +92/−29 · tests 187 lines vLLM pin v0.33.0

Verdict: #1357 holds up better to upstream changes; #1595 is easier to read

  • #1357 never changes what upstream sees. logits_indices and sample_hidden_states keep their real values, and the padded rows travel on the tensor itself. If upstream changes, the fast path quietly turns off and the existing, correct host path takes over.
  • #1595 hands upstream a padded index, or slice(None), in place of the real one. It then sends the true row count to compute_logits through mutable state on the wrapper. It is correct only while upstream uses logits_indices purely as a subscript followed by one compute_logits call. Every other consumer has to be found and excluded by hand. Two are excluded today. A third, sample_hidden_states, already holds the padded rows.
  • #1595 needs a torch-spyre bump it does not include. It relies on aten::index.Tensor (torch-spyre#5978, merged 6 Nov). Main pins f8a09bb (3 Nov), which is 55 commits behind that merge.
  • #1357's weak spot is that it intercepts too much. __torch_function__ catches every 1-D integer index on the hidden states, not just the sampling one. It also asks maintainers to understand tensor subclasses.

A good path forward: keep #1357's structure, and after the torch-spyre bump use the native index inside it. Details are under Suggested path.

Baseline · main today

The round trip both PRs remove

Option A

#1357: the hidden states know how to index themselves

For maintainability

  • Upstream sees only true values. logits_indices, sample_hidden_states and the attention metadata stay unpadded, so new upstream consumers of them just work.
  • The padded rows ride on the tensor they describe. They cannot get out of step with it, and no state lives on the wrapper between calls.
  • The decode shortcut checks the actual index (torch.equal against arange) instead of inferring it from counts.
  • If something breaks, the result is still correct. A dropped tag sends compute_logits down the existing host-pad path: slower, same answer.
  • It carries over to MRV2. Upstream's MRV2 uses the same expression, hidden_states[input_batch.logits_indices], and Spyre's MRV2 already shares _SpyreModelWrapper.
  • Works on the pinned torch-spyre. Its tests exercise the subclass alone, without patching upstream methods.

Against

  • It matches too broadly. Every 1-D int __getitem__ on the hidden states is padded to the logits row buckets. That includes upstream's EAGLE disable_padded_drafter_batch path, which can land on unwarmed widths. Values stay right.
  • It matches on the syntax upstream uses. A switch to torch.index_select(...) or hidden_states.index_select(...) skips the redirect.
  • A silent fallback is hard to see. An upstream .contiguous() or .to() before compute_logits drops the tag, and the D2H comes back with no error.
  • __torch_function__ subclasses are unfamiliar to many contributors. If the subclass ever enters a compiled region, Dynamo has to trace the override.
  • Once torch-spyre#5978 lands, the custom routing duplicates a native kernel. The #5978 description says as much.
Option B

#1595: the runner rewrites the index it gives upstream

For maintainability

  • It uses no tensor subclass or __torch_function__. The gather is ordinary PyTorch indexing backed by a torch-spyre kernel, so a reader needs no special knowledge.
  • That kernel checks bounds on the host. #5978 notes that an out-of-range device index faults the card.
  • Any other hidden_states[idx] upstream adds runs natively and is not forced onto the logits buckets.
  • It is somewhat smaller, and the padding is in one obvious place (pad_sampled_rows).
  • Syntax changes upstream don't matter. index_select or __getitem__ both accept a padded tensor.

Against

  • It gives upstream false values. Everything downstream of _prepare_inputs gets a padded index or a slice, which breaks the torch.Tensor annotation. Correctness depends on an exclusion list (kv_sharing_fast_prefill, aux hidden states) that someone has to update after each vLLM bump.
  • sample_hidden_states in ExecuteModelState now holds R_pad rows, or the whole body on decode. It goes to propose_draft_token_ids. Nothing in v0.33.0 reads it, but a future drafter would get padded rows without any error.
  • The true count is passed outside the data. _sampled_rows is written in _prepare_inputs and read by the next compute_logits, with no check that the tensor matches. A step that raises between the two, or any compute_logits call in between, mis-trims.
  • The decode check infers identity from counts plus bucket equality instead of checking the indices. It is right under today's vLLM semantics, but only implicitly.
  • It doesn't carry over to MRV2, which has no _prepare_inputs. There, logits_indices comes from combine_sampled_and_draft_tokens and also feeds fast_prefill.prepare and the input batch, so it would need a new hook with the same exclusion problem.
  • It needs a torch-spyre bump that is not in the PR. Its tests also monkeypatch GPUModelRunner._prepare_inputs, which ties them to upstream's 3-tuple return.

Recommendation

Suggested path

The thing to keep from #1357 is that it never lies to upstream. The thing to keep from #1595 is the native kernel. They fit together:

  1. Land #1357's structure: a wrapper-level, data-bound tag and no rewrite of logits_indices.
  2. After the torch-spyre bump that brings #5978, use plain indexing inside _gather_rows in place of select_rows. The row bucketing and the decode shortcut stay. #5978 itself suggests this.
  3. Narrow the interception. Have the runner record which index object it passed to upstream (without changing it), and redirect only that object. Other integer indexes then go to the native kernel unpadded.
  4. Make the silent fallback visible. After warmup, if a generate-mode compute_logits gets a Spyre tensor without the tag, log a warning once or fail a test. Otherwise an upstream refactor can bring the D2H back without anyone noticing.

This keeps the tensor subclass, slimmed to one job. Its __torch_function__ matches only the recorded index, pads it to a warmed row bucket or takes the decode shortcut, indexes with the native kernel and tags the result. The select_rows routing and the interception of other indexes go away. Dropping the subclass entirely would take a seam in upstream vLLM, such as a runner hook that selects the sample rows, which would be a good follow-up.

If #1595 is the one that lands, harden it: assert in compute_logits that hidden_states.shape[0] == next_bucket(_sampled_rows), reset _sampled_rows when each step starts, bump torch-spyre in the same PR, and add a vLLM-bump checklist item to re-audit every reader of _prepare_inputs's return value.
